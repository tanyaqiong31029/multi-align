# 金标准对齐基准（Gold Alignment Benchmark）

衡量「分句 → 句对齐」核心流水线的正确性，作为回归防线与质量名片。与 `agent-skill/scripts/pipeline_test.js`（工程断言）互补：回归测试保证**不坏**，基准回答**多好**。

> ⚠️ **如何解读本基准的数字**：这是一个**内部小型回归集**（自建用例、人工标注），衡量"已声明能力不被改动破坏"，**不是**在公开大规模语料上的通用准确率。真实语料（含翻译体差异、OCR 噪声、错段）上的表现以各用例类型分别看待，已知局限见文末。

## 运行

```bash
node benchmark/run_benchmark.js                # 打开报告
node benchmark/run_benchmark.js --min-f1 0.97  # 低于阈值退出码 1（CI 用）
node benchmark/run_benchmark.js --verbose      # 显示漏检/多检珠
node benchmark/run_benchmark.js --json         # 机器可读输出
```

## 数据集

`gold/alignment_gold.json`，当前 15 个用例、6 组语言对、约 1980 句（含 1 个 1800 句长文本用例）：

| 用例 | 语言 | 考察点 |
|---|---|---|
| zh-en-basic | 中↔英 | 基础 1-1；中英长度比例失衡下的鲁棒性 |
| zh-en-merge | 中↔英 | 2-1 合并（英文把中文两句译成一句） |
| en-fr-split | 英↔法 | 1-2 拆分（法文把英文一句译成两句） |
| en-de-numbers | 英↔德 | 数字锚点：全部句子含数字/年份，含德语小数逗号 `1,2` ↔ 英语 `1.2` |
| zh-en-srt | 中↔英 | 字幕时间轴锚点：台词 ±300ms 偏移 + 1-2 合并（去掉时间轴通道该用例不通过） |
| en-de-headings | 英↔德 | 学术结构：章节标题 + 有序列表标号（"1. Introduction" 不误切），每句一行形态 |
| zh-en-footnote | 中↔英 | 学术脚注：上标引注（¹²³）跟随句末标点归前句，[12] 引用不切分 |
| en-ocr-noise | 中↔英 | OCR 轻噪声：句末双空格、词间异常空格 |
| zh-en-para-shift | 中↔英 | 错段：中文 3 段 / 英文整段未分段 → 段落锚定失效 → 全局对齐兜底 |
| en-es-end-omission | 英↔西 | ⊘ xfail：文末一句漏译（1-0） |
| en-fr-mid-omission | 英↔法 | ⊘ xfail：中段孤立漏译（连锁错配的最病态场景） |
| en-de-num-omission | 英↔德 | ⊘ xfail：含独特数字（2035）的句子漏译——算法增强的首个目标用例 |
| zh-en-long-1800 | 中↔英 | 1800 句长文本：状态数超阈值强制走滑窗分块（alignLarge），每句含唯一节号 |
| zh-ja-kanji | 中↔日 | 共享汉字词汇相似度通道 |
| en-es-paragraphs | 英↔西 | 段落锚定（三段，段数一致） |

**标注格式**：`sentences` 为人工切定的句子序列（脚本会拼回文本、用生产分句器重切并断言一致——分句器改坏会在这里直接暴露）；`gold` 为珠（bead）标注 `[[[源下标...],[目标下标...]], ...]`；`paraGroups` 可选（声明分段以触发段落锚定）、`lines: true` 可选（每句一行重建文本，标题/列表的真实形态）、`srt: true` + `timing`（每句 `[开始ms, 结束ms]`）声明字幕用例；`xfail: true` 标注已知局限用例（见下）。

**xfail 机制**：标注 `xfail: true` 的用例若未得满分 → 记为"预期内"，**不计入宏平均、不触发 CI 失败**；若意外得满分 → 报 XPASS ⚡ 提示"已能解决，请移除标注"。这让已知局限留在基准里持续可见，又不污染回归信号。

**指标**：珠级 Precision / Recall / F1（预测珠与金标珠的集合匹配），总体取用例宏平均。新增用例请保持每类句对变换至少一例覆盖。

## 当前结果

12/12 计分用例 F1 = 100%（宏平均 100.0%，**内部小型回归集口径**；另有 3 个 xfail 已知局限用例单独报告）。CI 阈值设为 **F1 ≥ 97%**（仅计计分用例）：任何使对齐质量产生实质性退化的改动都会被拒绝合并。

## 路线图：1-0/0-1 检测（下一阶段首要算法升级）

三个 xfail 用例即增强目标。设计草案：为 1-1 珠引入**不对称信号惩罚**——当两侧数字集合不对称（一侧含他侧没有的独特数字）且词汇相似度≈0（兼容文种）时，给该珠加罚 `λ · signal`；调 λ 使 3 个 xfail 转正且其余用例零回归。风险：专有名词常无数字对应、音译形差异大，需在扩充的真实语料上标定 λ。滑窗修复（内部块无右填充，见下）是同一方向的前置工作——先让分块不制造人工错误，增强信号才有干净的评估环境。

## 滑窗分块的重要实现约束

`alignLarge` 内部块**无右填充**：右侧人工填充区会被 DP 用 1-2 链"吸收"而非删除（删除珠代价远高于合并珠），1800 句基准实测该缺陷 F1 88%→修复后 100%。窗口宽度 = 全局比例 × 块大小，锚定在真实已消费位置（bConsumed），接缝处自校正。末块消费全部剩余。

## 已知局限（路线图）

- **孤立的句中漏译/增译（1-0/0-1）不可靠**：纯长度统计模型下，删除珠的长度失配代价过高、且错配路径（2-1 + 位移）几乎总是更便宜——这是 Gale-Church 类算法的**原理性边界**，不是实现缺陷。经典解法是补充词汇/同源词锚点（hunalign、Champollion 路线）或句向量（LaBSE/Vecalign 路线）；两者均在路线图中，前者还受跨文种（如中↔英）无共享词汇的制约。
- 现有珠型罚分沿用 Gale-Church (1993) Table 5 标定，未针对多语（>2 版本）场景重标定。

修改 `js/aligner.js` 的代价函数或罚分表时，务必同时跑本基准与回归测试，并检查每个用例的逐珠差异（`--verbose`）。
